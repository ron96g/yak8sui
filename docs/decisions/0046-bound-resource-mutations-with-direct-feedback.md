# Bound resource mutations and report their outcome directly

Treat update, trigger, and delete as explicit foreground actions. While a mutation is pending, show a spinner and progress label on the initiating control, make the editor read-only, and disable competing detail actions. Apply one five-second deadline to the complete operation so an unavailable mutation endpoint or stalled projection cannot leave the resource dialog indefinitely blocked.

Do not treat the mutation HTTP acknowledgement as completion. Update responses identify the Kubernetes resource version returned by the write, and trigger responses identify the exact `triggered-at` value written by the action. The authorized detail projection exposes both operation tokens as structured fields. After acknowledgement, poll that projection at a short interval until the matching token is visible; delete completes when the projected resource is absent. Report observed completion and failures in a dismissible snackbar. Keep delete feedback outside the resource dialog so it remains visible after the observed delete closes that dialog. Timeout messages must state that the Kubernetes operation may still complete because ending browser observation cannot prove that the server or cluster stopped processing it; users should check the informer-backed observed state before retrying.
